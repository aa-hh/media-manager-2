# Pick a release: showing only releases for the searched episode

Research, 13 Oct 2026. Question from Alec: when Sonarr returns releases that are not for the episode searched, can Pick a release filter them out without hiding the right file when release numbering differs?

Short answer: yes, and no title parsing is needed. Sonarr already reads every release title, works out which of its episodes the release holds, and sends that answer with each release. Filter on Sonarr's answer, not on the SxxExx text. Keep the hidden releases one click away, because Sonarr's answer is wrong for box sets and DVD-numbered releases and nothing we have can always tell.

Versions read: Sonarr v5.0.0.2569 (prerelease, 12 Oct 2026, built from `develop` at `57816c1`) and Sonarr v4.0.20.3014 (current stable, 16 Sep 2026); Radarr `develop` at `af7814f`. Every Sonarr behaviour below is the same in both Sonarr versions unless marked v5. Sonarr links point at v5.0.0.2569.

## The rule

For each release, Sonarr parses the title, finds the series, then maps the release to its own episodes, translating scene numbers, absolute numbers, air dates and special titles on the way ([ParsingService.cs:176-270](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/Parser/ParsingService.cs#L176-L270)). It sends the result as `mappedEpisodeInfo` (one entry per episode: `id`, `seasonNumber`, `episodeNumber`, `absoluteEpisodeNumber`, `title`) and sets `episodeRequested` to true when any mapped episode is one the search asked for ([ParsingService.cs:263-267](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/Parser/ParsingService.cs#L263-L267), [ReleaseResource.cs:42-46, 58](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/Sonarr.Api.V3/Indexers/ReleaseResource.cs#L42-L58)). Radarr does the same for movies with `mappedMovieId` and `movieRequested` ([Radarr ParsingService.cs:119-121](https://github.com/Radarr/Radarr/blob/af7814f7a89ea46f21522f0a1b8bcdcf7644b8bf/src/NzbDrone.Core/Parser/ParsingService.cs#L119-L121), [Radarr ReleaseResource.cs:37, 48](https://github.com/Radarr/Radarr/blob/af7814f7a89ea46f21522f0a1b8bcdcf7644b8bf/src/Radarr.Api.V3/Indexers/ReleaseResource.cs#L37-L48)).

| Search | Keep the release when | Same test from data we already store |
|---|---|---|
| Episode | `episodeRequested` is true | `episodeIds` contains the searched episode id |
| Season | `episodeRequested` is true. Sonarr's season search asks for every episode of the season, monitored or not ([ReleaseSearchService.cs:98](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/IndexerSearch/ReleaseSearchService.cs#L98), called with `missingOnly` and `monitoredOnly` false at [ReleaseController.cs:217](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/Sonarr.Api.V3/Indexers/ReleaseController.cs#L217)) | `episodeIds` shares an id with the season's episodes |
| Movie | `movieRequested` is true (Radarr sets it when `mappedMovieId` equals the searched movie) | none; we do not keep `mappedMovieId` |

When the test fails, Sonarr and Radarr say why in `rejections`. The wording, identical in v4 and v5:

- Mapped to other episodes: `Episode wasn't requested: 1x6` or `Episode wasn't requested: 1x5-6`, in Sonarr's own season and episode numbers, unpadded ([EpisodeRequestedSpecification.cs:26-49](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/DecisionEngine/Specifications/Search/EpisodeRequestedSpecification.cs#L26-L49)). Usually alongside `Wrong episode` or `Wrong season` ([SingleEpisodeSearchMatchSpecification.cs:45-69](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/DecisionEngine/Specifications/Search/SingleEpisodeSearchMatchSpecification.cs#L45-L69)), `Wrong season` in a season search ([SeasonMatchSpecification.cs:33-43](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/DecisionEngine/Specifications/Search/SeasonMatchSpecification.cs#L33-L43)), or `Wrong series` ([SeriesSpecification.cs:29-33](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/DecisionEngine/Specifications/Search/SeriesSpecification.cs#L29-L33)).
- Not mapped at all: `Unknown Series`; `<title> matches an alias for series with TVDB ID: <id>`; `Unable to identify correct episode(s) using release name and scene mappings`; `Unable to parse release` ([DownloadDecisionMaker.cs:103-118, 145-156](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/DecisionEngine/DownloadDecisionMaker.cs#L103-L156)).
- Movies: `Wrong movie` ([Radarr MovieSpecification.cs:32](https://github.com/Radarr/Radarr/blob/af7814f7a89ea46f21522f0a1b8bcdcf7644b8bf/src/NzbDrone.Core/DecisionEngine/Specifications/Search/MovieSpecification.cs#L32)); `Unknown Movie. Unable to match to correct movie using release title.`; `Unable to parse release` ([Radarr DownloadDecisionMaker.cs:85, 122](https://github.com/Radarr/Radarr/blob/af7814f7a89ea46f21522f0a1b8bcdcf7644b8bf/src/NzbDrone.Core/DecisionEngine/DownloadDecisionMaker.cs#L85-L122)). Radarr matches a title only when the release year equals the movie's year or second year ([Radarr ParsingService.cs:166, 179, 237](https://github.com/Radarr/Radarr/blob/af7814f7a89ea46f21522f0a1b8bcdcf7644b8bf/src/NzbDrone.Core/Parser/ParsingService.cs#L166-L237)), so a wrong year reads as `Unknown Movie`, not `Wrong movie`. `edition` is parsed and sent but never checked.

Filter on the field, never on the wording. The wording compares the release's own numbers with the numbers Sonarr searched for, so a release Sonarr mapped to the right episode can still carry `Wrong season`, for example a TVDB-numbered release of an episode whose scene numbering differs ([ParsingService.cs:734-749](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/Parser/ParsingService.cs#L734-L749) maps it by TVDB number after the scene lookup misses). The wording is still the right text to show on a hidden release. All of these checks run at Sonarr's first priority level, so the wording is always present when the mapping fails ([SpecificationPriority.cs](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/DecisionEngine/SpecificationPriority.cs), [DownloadDecisionMaker.cs:190-200](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/DecisionEngine/DownloadDecisionMaker.cs#L190-L200)).

What our server had before this change:

- Sonarr already sends every field above in the reply to `GET /api/v3/release` that `src/server/releases.ts` makes. No new request is needed.
- `toRelease` (`src/server/releases.ts`) kept only the ids from `mappedEpisodeInfo`, as `episodeIds`, and dropped `episodeRequested`, `fullSeason`, `mappedSeasonNumber`, `seasonNumber`, `episodeNumbers`, `absoluteEpisodeNumbers`, `airDate`, `isDaily`, `isAbsoluteNumbering`, `special` and `sceneMapping`. For Radarr it dropped `mappedMovieId` and `movieRequested`.
- `episodeIds` already reaches the browser (`src/client/PickRelease.tsx:61-62`), so the TV half of the rule can run with no server change. The movie half needs `toRelease` to keep `movieRequested`.
- Searches stored before `episodeIds` was kept have no mapping data (`src/server/releases.ts`). A release with no mapping data must be shown, not hidden.
- Today the panel shows every release in Sonarr's order, dims rejected ones and shows the first rejection as the row's verdict (`src/client/PickRelease.tsx:157-169, 365-367, 712`). Only the quality filter hid rows (`:367, 581-586`).

Do not parse SxxExx in media-manager-2. Sonarr's parser has about 90 title patterns: `1x05`, `S01E05E06`, `S01E05-06`, split episodes (`S01E05a`), absolute numbers, air dates, `Part 1` mini-series, `103` naming and more ([Parser.cs:23-465](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/Parser/Parser.cs#L23-L465)). A text filter on SxxExx would wrongly hide every case in the table below except multi-episode files.

## Knowing a series has a discrepancy

From easiest to hardest. Each step says what it catches that the steps above it miss.

1. **Sonarr's episode scene numbers, already parsed.** `sceneSeasonNumber`, `sceneEpisodeNumber`, `unverifiedSceneNumbering` and `absoluteEpisodeNumber` are in our `Episode` type (`src/server/services/arr/episodes.ts:18-21, 48-51`) and the title page already marks `Scene S02E01` and `Scene numbering unverified` (`src/client/title/rows.ts:19-24`). The panel receives this episode list (`src/client/PickRelease.tsx:288`). Catches: per episode, every show TheXEM covers. `sceneAbsoluteEpisodeNumber` is in Sonarr's reply ([EpisodeResource.cs:31-35](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/Sonarr.Api.V3/Episodes/EpisodeResource.cs#L31-L35)) but not parsed.
2. **Sonarr series fields, in the reply but not parsed.** `seriesType` (Standard, Daily, Anime) and `useSceneNumbering`, which Sonarr sets true when TheXEM has a map for the series ([XemService.cs:96](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/DataAugmentation/Xem/XemService.cs#L96)). `parseSeries` drops both (`src/server/services/arr/series.ts:58-121`). Catches: which naming to expect (dates, absolute numbers) for the whole series, and a series typed wrongly, the daily-show gap above.
3. **The search reply itself.** Per release, Sonarr sends the numbers it read from the title (`seasonNumber`, `episodeNumbers`, `absoluteEpisodeNumbers`, `airDate`) next to the numbers of the episodes it mapped to (`mappedEpisodeInfo`), plus `sceneMapping` when an alias with a season offset matched ([ReleaseResource.cs:123-153](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/Sonarr.Api.V3/Indexers/ReleaseResource.cs#L123-L153), [AlternateTitleResource.cs](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/Sonarr.Api.V3/Series/AlternateTitleResource.cs)). Read numbers that differ from mapped numbers mean Sonarr translated the numbering. A not-mapped release whose episode number is past the season's last episode points to a box set with extra episodes. Catches: evidence on any series, in this search, including box sets nothing else knows about. Costs keeping more fields in `toRelease`. `sceneSource` exists in the reply but Sonarr never sets it ([ReleaseResource.cs:33, 108-166](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/Sonarr.Api.V3/Indexers/ReleaseResource.cs#L33)), so do not use it.
4. **Sonarr v5 episode orders.** v5 series replies carry `seasonType` (the order the owner chose, `official` by default) and `seasonTypes`, TVDB's list of orders for that series, each with `name`, `type`, `seasonNumbers` and `episodeCount` ([SeasonTypeResource.cs](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/Sonarr.Api.V3/Series/SeasonTypeResource.cs), [SeriesResource.cs:38-40](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/Sonarr.Api.V3/Series/SeriesResource.cs#L38-L40)). Sonarr fetches these through Skyhook, its own proxy in front of TVDB, so we need no TVDB key. More than one order, or a DVD order with a different `episodeCount`, means releases may follow another order. Catches: DVD and other orders on shows TheXEM does not cover. Only on v5, which is a prerelease today; stable v4 has neither field.
5. **TMDB episode groups.** Our TMDB key already works for `GET /tv/{tmdbId}/episode_groups`, which lists a show's other orders with a `type` (1 original air date, 2 absolute, 3 DVD, 4 digital, 5 story arc, 6 production, 7 TV) and counts, and `GET /tv/episode_group/{id}`, which lists each group's episodes with their original `season_number` and `episode_number` and an `order` ([TMDB docs](https://developer.themoviedb.org/reference/tv-series-episode-groups), [group details](https://developer.themoviedb.org/reference/tv-episode-group-details)). Sonarr gives us each series' `tmdbId` (`src/server/services/arr/series.ts:88`). Catches: alternate orders for Sonarr v4 owners, and an exact per-episode translation ("DVD S01E05 is aired S01E06"). Work: new client calls and a cache (`src/server/services/tmdb.ts` calls none of these today). TMDB's own numbering can differ from TVDB's, so an exact translation needs each TMDB episode's TVDB id and Sonarr's per-episode `tvdbId` ([EpisodeResource.cs:17](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/Sonarr.Api.V3/Episodes/EpisodeResource.cs#L17)); the TMDB per-episode `external_ids` call for that is from memory, not checked.
6. **TVDB directly.** `GET /series/{id}/episodes/{season-type}` with `default`, `official`, `dvd`, `absolute`, `alternate` or `regional` gives every order in Sonarr's own numbering ([TVDB v4 swagger](https://github.com/thetvdb/v4-api/blob/main/docs/swagger.yml)). Catches: exact translations with no TMDB-to-TVDB step. Needs a TVDB API key and, for user-supported keys, a subscriber PIN (same swagger, login section). Most work of the non-anime options, plus a new credential.
7. **Anime: Anime-Lists.** A public XML file on GitHub, updated 12 Oct 2026, maps each AniDB entry to a TVDB id, a default TVDB season and an episode offset, with per-episode mapping lists ([Anime-Lists README](https://github.com/Anime-Lists/anime-lists)). No key. Catches: anime releases numbered by AniDB entry (each part of a season counted from 1) that TheXEM does not cover. Work: high, and only anime gains. AniList's API has no TVDB episode mapping (one aggregator's table, not confirmed); Sonarr stores MyAnimeList and AniList ids on the series ([Series.cs:31-32](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/Tv/Series.cs#L31-L32)) but its v3 API does not send them.

Adds nothing:

- **TheXEM directly.** Its API answers without a key (`https://thexem.info/map/all?id=<tvdbId>&origin=tvdb`, checked live), but Sonarr already pulls the same maps ([XemProxy.cs:21](https://github.com/Sonarr/Sonarr/blob/v5.0.0.2569/src/NzbDrone.Core/DataAugmentation/Xem/XemProxy.cs#L21)) and stores them per episode (step 1).
- **Trakt.** Our client reads lists and genres only (`src/server/services/trakt.ts:113-127`). Trakt moved its TV episode data to TMDB around 2021 (community reports, no official notice found), so it knows no more than step 5.
- **MDBList.** Ratings only (`src/server/services/mdblist.ts:69-70`).
- **Plex.** A per-show episode ordering setting exists (TMDB aired, TVDB aired, TVDB DVD, TVDB absolute, per Plex forum posts), but our client only checks the connection (`src/server/services/plex.ts`), and the setting says how Plex reads files, not how releases are numbered.

## What the user sees

- The list shows releases that pass the rule. Season packs and multi-episode files stay, with Sonarr's reason (`Full season pack`) as today.
- Under the last row, one line gives the count of hidden releases with a Show button. Shown, they sit at the end, dimmed as rejected releases are now, each with Sonarr's reason first (`Episode wasn't requested: 1x6`, `Unknown Series`). This keeps AA-49's check that a rejected release can still be selected and grabbed.
- When the rule would hide every release, show them all and say none matched, so an odd-named box set is never behind an empty state.
- When Sonarr knows this episode's release numbering differs (scene number on the episode, or a second order in v5), say so above the list, for example "Releases may number this episode S02E01".
- Grab on a hidden release goes through the override (AA-53) set to the searched episode or movie. A plain grab would download it for the episode Sonarr matched while our grab record names the searched one (`src/server/grabs.ts:126-134`), or fail for an unmatched release.
- Open question for Alec: in a season search, should single-episode releases from that season also be hidden? Sonarr accepts them, and the rule keeps them.

## Draft Linear ticket

**Title:** Hide releases matched to another episode, season or movie in Pick a release

**Project:** P-AA-3 (V1 · Search, release selection and replace). **Parent:** AA-31 Search, release selection and replace. **Related:** AA-49 Show the release list for Pick a release; AA-53 Override what a release counts as before grabbing. No existing ticket covers this (searched team AA for episode, scene, numbering, filter, wrong and anime).

**Goal**
Pick a release lists only releases for what was searched, without losing the right file when release numbering differs from Sonarr's.

**Scope**
- `toRelease` keeps Sonarr's `episodeRequested` and Radarr's `movieRequested` (`src/server/releases.ts:109-143`).
- Pick a release hides releases where that flag is false. A TV release stored without the flag falls back to `episodeIds`: the searched episode id, or any id of the searched season. A release with neither is shown.
- A line under the list gives the hidden count with Show; shown releases go at the end, dimmed, each with Sonarr's or Radarr's reason first.
- If every release would be hidden, all are shown with a note that none matched.
- A notice above the list when the searched episode's scene numbers differ from its own (`sceneSeasonNumber`, `sceneEpisodeNumber`, `unverifiedSceneNumbering`, already in the panel's episode list).
- Grab on a hidden release opens the override set to the searched episode or movie.

**Rule**
Keep a release when Sonarr's `episodeRequested` (or Radarr's `movieRequested`) is true. Sonarr sets it after mapping the release to its own episodes, through scene numbers, absolute numbers, air dates and special titles, so scene-numbered, anime, daily and special releases pass. Never parse release titles in media-manager-2, and never filter on rejection wording.

**Exceptions**
- Season packs and multi-episode files containing the episode: kept (Sonarr maps them to every episode they hold).
- Partial season packs, box sets with extra or merged episodes, and DVD-numbered releases on an aired-order series: Sonarr maps them wrongly or not at all, so they are hidden. They stay reachable through Show and grab through the override.
- Releases Sonarr could not match (`Unknown Series`, `Unable to parse release`, `Unable to identify correct episode(s)...`): hidden, reachable, grab through the override.

**Exclusions**
- No new integrations (TMDB episode groups, TVDB, Anime-Lists) and no Sonarr v5 episode order fields; separate ticket if wanted.
- Layout of the count line and notice comes from the design file, not this ticket.

**Acceptance**
- Episode search: a release whose `episodeRequested` is false is hidden and counted; a single-episode release, a multi-episode file containing the episode and a season pack of its season are shown.
- A release named with scene numbers that Sonarr mapped to the searched episode is shown.
- Season search: a release mapped only to another season is hidden.
- Movie search: a release with `movieRequested` false is hidden.
- A stored search from before this change hides nothing it cannot judge.
- When every release fails the rule, all are shown with the note.
- Show reveals the hidden releases with their reasons; each can be selected and grabbed (AA-49).
- Grabbing a hidden release sends `shouldOverride` with the searched series and episode (or movie), and the grab record names the same target.
- `tests/production.test.mjs` release replies carry `episodeRequested` and `movieRequested` as Sonarr and Radarr send them, with a case for each exception above.

**Dependencies**
Design frame for the count line and the notice in the releases design file (design before UI code). AA-53 override grab.
