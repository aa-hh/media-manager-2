# Critique: Desktop / TV overview: episode details (c9Z57)

Assessment A only (design review), from the 1440x900 screenshot plus PRODUCT.md, CONTEXT.md, the direction contract and docs/design/sonarr-radarr-review.md. No detector run (not part of this brief).

## Design specificity verdict

Specific to this product. The episode table, the inline version comparison (quality, group, HDR, audio, custom format score, seeding against the hit and run clock) and the history line that names the exact release and tracker could not move to another app unchanged. The red "PHD 41h of 72h, hit and run risk" cell is the direction contract's colour rule doing its job: red appears once and means risk.

Where it slips: the timing-tower idea has turned into "every cell is a chip". White filled chips are used for monitored (ON, ten times), quality (2160p, nine times), the search key, and the selected season tab, so the solid-white treatment no longer marks anything as special. The brightest thing on screen is the "Search season 2" button and the column of ON chips, neither of which is the reason this screen is open.

## Cognitive load

Failures (4 of 8, high):
- Single focus: the expanded episode competes with the header button, 20 per-row icon buttons, the result tower and the downloads dock.
- Visual hierarchy: white chips (ON, quality, header button, season tab) all carry top weight; the expanded detail panel, the thing the user opened, is grey on graphite and visually quieter than the rows around it.
- Minimal choices: inside the expanded episode, 3 buttons in its header, a trash icon, a "Mark as failed" button, plus the row's own 2 icons still visible: 7 actions. Across the visible pane, every row offers 2 more.
- Progressive disclosure: per-row search and list icons repeat on all 10 rows even though Enter already opens the same actions inline.

Passes: chunking of the version table, grouping of the expanded panel (bordered), working memory (all comparison data is co-located), one-at-a-time (only one episode expands).

Decision points over 4 options: expanded episode (7 actions), top bar (5 nav items plus search, all at once with the left key hints and dock).

## Emotional journey

The owner comes here mostly when something looks off. The answer to "is anything wrong with this show?" exists (red hit and run cell, "below cutoff" on episode 8, downloading on 7) but it is buried in a table where 6 of 10 status cells say "meets profile". Calm rows should read as calm by being quiet, so the 3 that need attention jump out.

## Strengths

1. Inline episode details instead of a modal, exactly as the owner decided: versions, history and actions sit under the row, Esc closes, the rest of the season stays in view.
2. The version table answers the real question (which file do I have, is it safe to delete) in one row each: quality, group, HDR, audio, score, and seeding against the tracker's 72h rule, with risk in red text and words, not colour alone.
3. History lines are plain sentences that name the cause ("grabbed by hand as a second version", "repack grabbed by automatic search ... replaced the first file"), which is the "fix it, then tell" principle in practice.

## Priority issues

**[P1] Repeated cells that carry no information dominate the table.**
- Why: ten white "ON" chips and six "meets profile" strings are the loudest, most repeated things on the screen, yet they say "nothing to see". The owner's concern about clutter is mostly this.
- Fix: show monitoring only when it differs from the header ("Monitored: all future episodes"); an unmonitored episode gets a dim "off" marker, monitored rows get nothing. Leave the status cell blank (or a faint dot) for "meets profile"; keep words only for exceptions (below cutoff, downloading, missing, manual download, finale/premiere). Drop the MONITORED column header entirely if no exceptions exist in the season.
- Command: /impeccable distill

**[P1] Per-row action icons repeat on every row.**
- Why: 20 icon buttons (search, list) in a right-hand column draw the eye down the whole table and duplicate what Enter already reveals in the expanded row with labels and keys. They also put the dangerous trash icon in the same column as harmless search icons.
- Fix: remove the per-row icons. Show search and pick-a-release only on the focused or hovered row (or only inside the expansion, which already has them). Move the second-version delete into the expansion's version row, as a labelled "Delete second version" text button, away from the search buttons.
- Command: /impeccable distill

**[P1] Two names and one key for the same action at two scopes.**
- Why: "Search season 2" (A) in the header and "Search automatically" (A) in the expanded row are both Sonarr's automatic search. CONTEXT.md fixes the button label as "Search automatically". With the same key, the owner cannot predict whether A searches the episode or the whole season.
- Fix: label both "Search automatically", with the scope as a quiet suffix ("Search automatically: season 2" / "...: this episode"). Make A act on the focused scope (episode when one is expanded), and say so in the hint. Demote the header button from solid white to the outlined style used in the expansion; it is not the primary job of this screen.
- Command: /impeccable clarify

**[P2] Chrome repeated from other screens takes a third of the width and the bottom of the page.**
- Why: the left result tower shows 2 results and about 560px of empty column, plus 5 key hints. The downloads dock lists The Bear and Andor, unrelated to this show, and repeats Severance S02E07, already shown live in the episode 7 row. Together they push the episode table into the middle 60% of the screen.
- Fix: collapse the result tower to a thin strip (or hide it) once a title is open; `[` and `]` already move between titles. Cut the key hint list to a single "? keys" hint. On a title page, shrink the dock to one summary line ("3 downloading, 41.6 MB/s") that expands on demand; the top bar already carries the speeds.
- Command: /impeccable layout

**[P2] The expanded episode is quieter than the rows around it.**
- Why: it is the thing the user asked to see, but its text is small grey on the same graphite, and two highlight boxes (the episode row and the 10 Feb history row) both look focused, so it is unclear where keyboard focus is.
- Fix: give the expansion a slightly lighter ground, white text for the version rows, and one focus outline only. Keep the history row's "Mark as failed" visible on focus, not as a second permanent box.
- Command: /impeccable polish

## Persona red flags

**Alex (power user):** A means two different things depending on what is expanded, with nothing saying which. `[` `]` and season switching keys are not shown, while generic ones (search, move, open) take the hint panel. Per-row icons invite the mouse in a keyboard-first app.

**Sam (accessibility):** Small grey text at roughly 11px on dark graphite (meta line, history lines, the season-button explanation, "searches when it airs") is likely below 4.5:1. Two simultaneous highlight boxes make keyboard focus ambiguous. Icon-only search, list and trash buttons need labels. Dimmed icons on episodes 9 and 10 (disabled?) give no reason.

**The owner on a normal evening (mostly monitors, digs in when something breaks):** opens Severance to check all is fine. The three things worth knowing (episode 7 downloading, episode 8 below cutoff as a manual download, a second version at hit and run risk) are spread across a table where every other row shouts "ON" and "meets profile". The answer takes a scan of the whole table instead of a glance. The trash icon next to that risky second version is the one control they could hit by accident on the way to the search icon.

## Minor observations

- Header lacks size on disk and continuing/ended, which the owner's screen decisions list for the TV overview; the other header actions (history, monitoring options, edit, delete, refresh, rename) are also absent. Absence helps clutter here; put them behind one "Actions" key rather than adding buttons.
- Season tabs read "Season 2 7/10 +2 versions": "+2 versions" belongs in the episode rows, not the tab.
- "+1600 · Atmos, DV, repack" score has no label; "score +1600" reads faster.
- Episode 8 says "below cutoff · manual download". The owner's decision says manual downloads never appear as below cutoff; this row contradicts it.
- "Fri 21:00" and "Fri +7d" mix two date styles in one column.
- The "2 results / Movies + TV" header in the tower repeats what the two rows already show.

## Questions

1. If monitored state and "meets profile" only appeared as exceptions, would the owner miss them, or would the three real issues on this season finally stand out?
2. Does the left result tower need to stay open once a title is chosen, given `[` and `]` already move between titles?
3. Should the downloads dock be per-title on a title page (only this show's torrents), with the global list one key away?
